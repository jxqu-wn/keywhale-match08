## 对六项问题的核对

1. “全明星只能到篮球”来自旧PROFILES的手写正则与first-match/break，并非原数据限制。强路由过滤掉冰球Schema候选及相似案例。5597、5651的实际同题案例仍已注入，但后续工具均沿错误域调用。
2. 100及以下、最低配送费用、基序、用户数量、图像数量等修正都有明确问题/字段依据，不应为标签一致撤回。
3. 日期knowledge 200从赛题压缩包、raw到processed逐项相同，本身未标明两种格式所属表。4726旧提示词实际包含200，另有movies_total_gross/revenue的无关知识。无法从现有记录知道模型内部选择理由；只能确认它在没有字段样例时改了案例表达式。
4. 旧系统同时要求根据参数修改逻辑、实体去重、按常识时间解析，缺少对同题语义与泛化规则冲突的复核。格式/EXPLAIN检查无法替代LLM语义审查。
5. 新流程按实际案例引用推断多域候选；初始Schema候选优先同题引用；相关案例默认按需请求；知识过滤明确属于未查表的条目；原始证据仍保留。
6. 全44题已经独立标注源问题、模型问题、评审问题和不确定性。不能把22%全归为合理偏差，也不能把源问题题目视为自动正确。

## 实验与限制

按需注入/案例复用的第一次v3验证已保存：200题中194题完成，6题因不完整动作JSON耗尽步数。194题里11题仍与原标注有偏差，但这个数字不能作为改进成功的依据；3359、5177、5929出现恢复错误案例的行为。

对“源数据有错但模型较好”的题，复制标签会损害答案。已在代码中改用独立LLM基于题意、Schema、知识复核，且复核员同样不把案例当作标准答案。该后续版本只通过本地测试，尚未进行真实API验证；用户要求停止追加试验后未运行194题后续验证。

失败记录保留：[v3失败记录](../../runs/react-v3-sqlite-random200-seed42/failures.json)。生成脚本不再自动重试失败题或网络失败；同一失败连续发生两次且没有进展时终止并保存。原来16步耗尽的轨迹保持不变。
