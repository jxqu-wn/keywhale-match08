## 实际调整

本轮保持本地预处理、关键词检索、ReAct工具循环及独立LLM语义复核。程序解析原始Schema中的表、字段、约束和注释，训练问答附加库表引用，知识保留原文，字典按匹配值返回相关行；模型通过工具获取片段。原文件路径、记录ID和SHA256用于溯源，不要求模型直接读取 `data/raw/`，也不向模型注入整份Schema文件。

暂停使用人工修订示例和知识、人工冲突决议、教育年度合并规则及CTE、字段裁定、营业时间辅助SQL、固定知识ID补齐和主题字典触发规则，以及按题目硬编码的业务校验。普通模型生成和ReAct均默认使用 `--evidence-mode raw-only`；原修订文件保留，可用 `--evidence-mode reviewed` 恢复。通用格式、只读限制、SQLite原始DDL编译及ES结构检查保留。

审计本轮283份生成及复核请求：发现的知识文本和问答查询均与原始文件一致，所有2830次来源记录均指向 `data/raw/`，未发现人工修订或非空业务规则字段注入。重复对话中的同一记录会被多次计数；来源记录数不是独立文档数。工具说明中的修订和合并视图指令也已删除。

## 12题不一致原因

11题首次提交检查时与原答案相同，随后被语义复核要求修改；只有3772在首次检查前由生成模型主动修改。本轮差异主要来自模型对题意、原始知识及查询行为的再判断。

| 题号 | 本轮修改及原因 | 对结果的判断 |
|---|---|---|
| 4478 | 按知识1416/172增加 `result='Winner'`，年份改为整数比较。原答案没有排除提名。 | 有同年同奖项提名记录时会缩小结果；获奖筛选更贴合题意。 |
| 3772 | 模型主动将发行关系条数改为 `COUNT(DISTINCT game_id)`。此次没有使用人工修订SQL。 | 重复发行关系会改变发行商排名；没有重复时可能相同。 |
| 4759 | 复核认为多次上映会导致重复计数，要求先按电影标题汇总票房。 | 通常等价。电影标题在characters中为主键，原式与新式都是汇总同一批票房，复核的“比例失真”理由不成立。 |
| 5688 | 复核删除TeamVsTeam连接，直接返回球队当年 `W/G`。 | 单一球队当年有对手记录时，原式重复同一胜率再求平均，与新式相同。无对手记录等边界另需判断。 |
| 4554 | 补查Credit/Episode后加入第20季、演员类别Cast及去重。 | 原答案仅筛出生信息；是否减少结果取决于匹配人员的参演记录。 |
| 4358 | 将属性关系条数改为独立的Mesa商家占比，并列出属性值明细。 | 原答案混合聚合和裸属性列，本轮修改百分比及结果行数；保留两列，未再添加上一轮的business_id。 |
| 3521 | 根据“rank数值越小越好”将ASC改为DESC；保留DSF。 | 排序会影响年份，但仍没有按year连接比赛与球队，可能关联其他年份。DSF在原知识58/1316中的解释也冲突，整体正确性尚未解决。 |
| 3453 | 复核指出仅按Match_Id连接会把同场所有球员当作低分击球者；补查Ball_by_Ball，以Striker及逐球组合键关联。 | 有明确Schema依据的修正，避免把其他参赛球员错误返回。 |
| 6015 | 根据“只能在2号店”加入NOT EXISTS排除其他店库存，并用EXISTS避免库存副本重复。 | 原答案仅要求2号店有库存；本轮收紧电影集合，符合“只能”的含义。 |
| 4442 | 按原始知识把active从小写true改为True，排除BYOB的None/No/FALSE值。 | 大小写和属性值条件会影响数量；原问答与原知识冲突仍存在。新过滤也遗漏False等否定形式。 |
| 5988 | 原答案返回国家，复核要求返回洲；生成CASE国家映射，后续移除Ecuador的北美映射并补充United States。 | 返回内容发生实质变化；映射只覆盖部分国家，未覆盖时仍返回NULL，模型修正不等于完整可靠的映射。 |
| 3295 | 将比赛角色记录计数改为不同球员计数，包含CaptainKeeper等角色；本轮未增加ROUND。 | 改变比例，有去重依据；但仍使用INNER JOIN，无参赛记录的1977年出生球员被排除在分母外。 |

人工语义归类为：2题通常等价（4759、5688），7题很可能影响结果（4358、3521、3453、6015、4442、5988、3295），3题取决于具体数据（4478、3772、4554）。因此40题中有10题（25%）存在潜在结果差异。**25%是语义分析得到的潜在差异占比，不是真实数据库测量值或准确率。**

使用原始SQLite DDL构造12组小数据执行原答案与本轮查询：2组相同，10组可以产生不同结果。例如4358原答案为一行 `100%, Yes`，本轮为两行 `50%, Yes` 和 `50%, WiFi`；3453原答案包含实际击球者与同场其他球员，本轮只返回实际击球者。构造数据用于展示机制，不能据此统计比赛数据库上的实际差异率。

## 复核流程的具体问题

### 首次复核前的候选与原始答案

从已保存的 `trace` 提取40题首次 `check_query` 的候选：39题与原始训练答案完全一致，仅3772不同，首次候选的文本不一致率为 **1/40=2.5%**。最终答案不一致率为 **12/40=30%**。

被语义复核打回的11题，其首次被打回的候选全部与原始训练答案一致，即该11题首次打回候选的不一致率为0%。逐次打回事件共17次，其中11次候选与原答案一致，另外6次是修改后再次被打回。

唯一最初就不同的3772，将发行关系记录计数改为不同 `game_id` 计数，首次复核直接通过。由此可见，本轮相对原标注新增的11道不一致均发生在复核要求修改之后。但文字一致性不能证明业务查询正确，本轮又保留了同题答案参与检索，该统计主要反映复用标注和后续改写的程度。这是历史候选提取，不是关闭复核后另跑的实验。

[首次候选、打回候选及最终答案逐题对照](../../artifacts/runs/evaluation/sqlite-train40-deepseek-flash-raw-only-20261010/pre_review_comparison.json)；[复核前40题预测提取](../../artifacts/runs/evaluation/sqlite-train40-deepseek-flash-raw-only-20261010/pre_review_predictions.json)。原逐题记录、生成响应和语义复核请求仍保留。

移除人工规则后仍有30%文本不一致，主要原因是语义复核会继续依据题目和原始资料改写训练答案，而原始标注本身存在缺漏或与知识冲突。

同时，复核并不稳定。4358共检查5次：复核先建议使用LEFT JOIN，随后又反对百分比与属性明细共同返回，最终接受了标量百分比与明细共同返回的写法。3521检查4次，排序改正后围绕DSF冲突反复要求修改，最后接受仍缺year关联的查询。4759则将本来基本等价的线性汇总误判为重复统计。

与上一轮相比，本轮4358取消了额外输出列、3295取消了未要求的四舍五入，3453修正了明显关联问题；但3521保留年度关联缺漏，3295没有覆盖全部出生于1977年的球员，4442仍有否定值过滤缺口。因此目前不能从30%这一比例断言模型水平提高或下降，也不能把与训练答案更一致视为一定更正确。

后续值得优先处理的是复核的证据判断和误报：区分“可证明会改变题意”与“等价改写或资料歧义”；避免同一合理查询因解释措辞变化被反复否决；对没有解决的关联、分母和枚举缺口明确保留待确认状态。以上为分析结论，本轮没有据此人工修改生成结果。
